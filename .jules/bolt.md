## 2024-05-24 - [Job Parser Performance: Pre-compiling Regexes]
**Learning:** `cli/integrations/job_parser.py` was previously recompiling numerous complex regular expressions for salary, experience levels, job types, and bullet points on every function call. This caused unnecessary CPU overhead, especially given the scale of data or repeated operations typical in a job parsing context. Pre-compiling them to module-level constants provided a measurable speedup. Additionally, modifying generic extraction functions to accept both `str` and `re.Pattern` allows retaining flexibility while reaping the benefits of the pre-compiled patterns.
**Action:** When working on extraction or parsing logic anywhere in the codebase, always check if regexes can be pre-compiled and lifted out of the function scope. Update function typing to `Union[str, re.Pattern]` to support smooth refactoring towards pre-compiled constants without breaking existing string-based usages.
